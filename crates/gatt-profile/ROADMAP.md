# gatt-profile roadmap

A no-I/O model of a peripheral's GATT table, a plain-text snapshot format with a parser and writer, and a
flattening into handle-ordered attributes for a future `att-server`. No Bluetooth specification text was
available, so every anchor that would be a standard is `[unread]`. Break notes say what was changed to make the
named test fail (all restored afterwards).

Format, one directive per line, `#` comments, free indentation: `device-name`, `adv-name`, `adv-service UUID`,
`service UUID [primary|secondary]`, `characteristic UUID PROPS [value=HEX]`, `descriptor UUID [value=HEX]`.
Fixtures (`fixtures/*.gatt`, each citing its source in a header comment): `fff0_serial` (FFF1 notify with CCCD,
FFF2 write; obd-bridge `docs/ble-re.md` and the vendor's public adapter notes), `obd_dis_serial` (the same plus
GAP, GATT and Device Information), `nordic_uart` (128-bit UUIDs, Nordic's public NUS page, a secondary service),
`hm10_ffe0` (single FFE1 that notifies and is written) and `gap_gatt_baseline`. `fixtures/malformed/` holds one
file per failure, each opening with `# expect: <line> <ErrorKind>`.

Format version 1. A file may open with `gatt-profile N`; without it the file is version 1. A reader refuses a
newer version. Within a version, directives and options whose names start with `x-` are ignored; anything else
new bumps the version. The writer always emits the header.
